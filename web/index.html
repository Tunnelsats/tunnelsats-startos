Lightning Routing & Gateway Setup Guides

Step-by-Step StartOS 0.4.0 Native Gateway Configuration:

  1. Configure Companion Service: Open Services → TunnelSats → Configure, paste your downloaded .conf, and click Save. The service validates your configuration and automatically injects the required markers (# StartTunnel & # inbound: yes).
  2. Add Gateway in StartOS: Navigate to System → Gateways → click Add Gateway → choose WireGuard and paste the configuration carrying both inbound markers (StartOS uses these markers to auto-classify the gateway as Inbound/Outbound for Lightning port forwarding). Connect the gateway.
  3. Open Firewall (Peer Interface): Open your target node (LND or Core Lightning) → Interfaces → Peer Interface, toggle <VPN_IP>:9735 to ON, and click "Later" on the port check prompt.
  4. Set Outbound Policy Routing (Required for Full Egress Privacy): Open your target node → Actions → Set Outbound Gateway → select your TunnelSats gateway to route all outbound peer connections and gossip through the VPN and prevent residential IP leakage.
  5. Inbound Lightning Traffic: Inbound connections to your TunnelSats port automatically forward to port 9735 on your node.
Host-Managed Privacy: StartOS manages kernel WireGuard encapsulation and outbound policy routing natively. IPv6 traffic is automatically blackholed by StartOS when routing through an IPv4-only gateway to prevent ISP leaks.

Frequently Asked Questions

How do I set up and activate TunnelSats on StartOS 0.4?

Setup consists of five simple steps across TunnelSats, StartOS Gateways, and your Lightning node:

  1. TunnelSats Configure: Go to ⚙ → Configure in TunnelSats. Paste your WireGuard .conf file, toggle Enable TunnelSats to On, select your target node, and click Save. Inbound markers (# StartTunnel & # inbound: yes) are automatically added, and a copyable config is provided.
  2. StartOS Gateway: Go to System → Gateways, add or update a WireGuard gateway, and paste the configuration. Connect the gateway.
  3. Target Node Announcement: Accept the automated 1-Click Task prompt on your StartOS dashboard to advertise your endpoint, or enter it manually in your target node (e.g. LND → Config → Custom External Host).
  4. Firewall Port Toggle: Go to your target node (e.g. LND → Interfaces → Peer Interface), find your TunnelSats public IP (<VPN_IP>:9735), and toggle it ON. When StartOS prompts to test port 9735 in "Address Requirements", click "Later".
  5. Set Outbound Gateway (Full Egress Privacy): Go to your target node (e.g. LND → Actions → Set Outbound Gateway), and select TunnelSats. StartOS defaults outbound traffic to Auto; setting this action pins all outbound peer connections, gossip, and ping/pong packets to the VPN tunnel, eliminating home IP leaks.
I saved my config but the tunnel shows "Disconnected" or port closed — what do I do?

Work through these verification steps in order:

  1. Check the Host Gateway: Ensure your WireGuard tunnel under System → Gateways is connected.
  2. Verify Peer Interface Public Address Toggle: In your target node (e.g. LND → Interfaces → Peer Interface), verify that the toggle for <VPN_IP>:9735 is switched ON. If this toggle is off, StartOS firewall blocks incoming traffic.
  3. Verify Multi-Node Port Allocation (9735): StartOS routes TunnelSats incoming connections to internal port 9735. If you have both LND and Core Lightning installed, whichever was installed first holds port 9735. Ensure your desired target node holds internal port 9735.
  4. Check Custom External Host: Confirm your node advertises your TunnelSats external host and port under Config → Custom External Host.
  5. Restart Services: In StartOS, restart TunnelSats and your Lightning node after updating gateway bindings.
How do I configure the Custom External Host and Peer Interface in StartOS?

StartOS handles external host announcement and firewall port forwarding cleanly via the UI:

1. Announce Endpoint (Custom External Host)

  1. In the StartOS dashboard, open your LND or Core Lightning service page.
  2. Navigate to Config → Custom External Host (for LND) or General Settings (for Core Lightning).
  3. Enter your TunnelSats endpoint: tunnelsats_ip:tunnelsats_port
  4. Click Save. StartOS advertises this address to Lightning peers so they can connect.

2. Open Firewall (Peer Interface Toggle)

  1. In your Lightning node service page, click Interfaces → Peer Interface.
  2. Locate your TunnelSats public IP address (<VPN_IP>:9735) in the list of available addresses.
  3. Toggle the address to ON. When StartOS displays the "Address Requirements" modal asking to test port 9735, click "Later". StartOS tests generic external port 9735, which is not open on the VPN server, but clicking "Later" successfully enables the firewall rule for your assigned TunnelSats port.

3. Set Outbound Gateway (Full Egress Privacy)

  1. In your Lightning node service page, click Actions → Set Outbound Gateway.
  2. Select your TunnelSats gateway and confirm.
  3. StartOS defaults outbound traffic to Auto; assigning TunnelSats ensures all outgoing peer connections, gossip, and ping/pong packets route through the VPN tunnel, eliminating home IP leaks.
Why does the StartOS "Address Requirements" port test fail when enabling the Public peer interface?

The StartOS built-in test probes external port 9735, which is not mapped to your node.

When you toggle the Public switch ON, StartOS assumes a 1:1 NAT model and attempts to test <VPN_IP>:9735 from an external server. However, TunnelSats provides dedicated port mapping using a unique high port (e.g. server.tunnelsats.com:24556 → internal 9735).

Because external port 9735 is closed on the WireGuard server, clicking "Test" will report a failure.

What to do: Click "Later". This saves and enables the public interface forwarding rule in StartOS nftables. Your node is now fully reachable on your assigned TunnelSats port!

Why does port forwarding fail if both LND and Core Lightning are installed?

StartOS assigns internal listening ports on a first-come, first-served basis:

Standard Lightning communication occurs on internal port 9735. TunnelSats WireGuard gateways forward incoming peer traffic specifically to port 9735.

If multiple Lightning implementations are installed (e.g. Core Lightning was installed before LND), the first installed node receives internal port 9735, and subsequent nodes are assigned arbitrary high ports (e.g. 63989).

Solution: Only the node holding port 9735 receives TunnelSats traffic. If you want LND to receive tunnel traffic on a system where Core Lightning was installed first, Core Lightning must release port 9735 (or be uninstalled) so LND can bind to preferred port 9735.

Is TunnelSats a general VPN for all my StartOS traffic?

No. TunnelSats is purpose-built exclusively for Lightning Network routing.

It tunnels only your Lightning node's inbound peer connections (LND or CLN) — not your Bitcoin node, not your other StartOS apps, and not your general internet traffic. Your Bitcoin node (bitcoind) continues to use Tor as normal.

This is by design: TunnelSats gives your Lightning node a stable, reachable clearnet identity for channel gossip, without exposing your home IP or routing all your traffic through a third party.

If you need a general-purpose VPN for all StartOS system traffic, look for WireGuard or OpenVPN packages in the StartOS app store.

What happens if my subscription expires while the tunnel is active?

This is the most important thing to plan for. When your subscription expires:

  1. The WireGuard tunnel drops — your node can no longer receive inbound connections via the TunnelSats IP.
  2. However, your Lightning node's Custom External Host setting in StartOS still points to that now-dead endpoint address.
  3. Your node will broadcast an unreachable address to the network, causing peers to fail to connect and potentially affecting channel health.

What to do before expiry:

  • Watch the countdown timer on this dashboard — it turns amber when under 30 days remain.
  • Renew at tunnelsats.com and paste your new config before the old one expires.
  • Or, if you won't renew: disable TunnelSats via ⚙ → Configure (set Enable to Off), clear the Custom External Host field in your Lightning node (Actions & Config → Configuration → Custom External Host), and save.
Are my WireGuard config and settings preserved if I uninstall the app?

No — uninstalling TunnelSats from StartOS will delete your configuration data, including your pasted WireGuard config and the enabled/disabled state.

This is a StartOS platform behaviour: when a package is uninstalled, its data volume (/data) is removed along with the container.

Before uninstalling, you should:

  1. Copy your WireGuard .conf content from ⚙ → Configure → WireGuard Configuration and save it somewhere safe.
  2. Disable the TunnelSats tunnel (set Enable to Off and save) so your Lightning node falls back to Tor/clearnet.
  3. Clear the Custom External Host field in your Lightning node settings (Actions & Config → Configuration → Custom External Host).
  4. Only then uninstall TunnelSats.

⚠ Your subscription itself (purchased at tunnelsats.com) is not affected by uninstalling the StartOS app. If you reinstall, simply paste your .conf file again.

Can I run LND and Core Lightning (CLN) simultaneously through the same tunnel? How does switching work?

No, running LND and CLN in parallel through the same TunnelSats subscription is not supported. A single WireGuard tunnel receives traffic on one assigned public port and forwards it to a single target container.

Real-Time Switching: You can switch between LND and Core Lightning at any time in ⚙ → Configure by selecting a different Target Lightning Node.

When you switch, TunnelSats updates StartOS native gateway routing in real-time. Inbound connections arriving on your TunnelSats VPN address are immediately re-routed to your newly selected target node without needing to reconfigure WireGuard keys or purchase a new subscription.

Does TunnelSats support IPv6? What happens if I advertise an IPv6 address?

No, TunnelSats is an IPv4-only WireGuard VPN service.

Because TunnelSats provides an IPv4-only WireGuard tunnel, any IPv6 traffic or IPv6 address advertised on your Lightning node will route directly through your home internet service provider (ISP), bypassing TunnelSats completely.

Security Recommendation: Keep your Lightning node configured with IPv4 / Tor only to protect your home location. If you explicitly want dual-stack connectivity and accept revealing your home IPv6 address to peers, turn ON Allow Home IPv6 Coexistence under ⚙ → Configure.

How do I independently audit and verify my node's network endpoints via CLI?

You can independently audit your Lightning node's announced endpoints and active network interfaces directly from the StartOS host terminal using start-cli.

1. Inbound Lightning Gossip Announcement Audit

Confirm your node persistently announces your TunnelSats external domain and port to network peers:

LND Announcement Check: 
start-cli package attach lnd -- lncli --rpcserver=127.0.0.1:10009 getinfo
Core Lightning Announcement Check: 
start-cli package attach -i lightning c-lightning -- lightning-cli getinfo

Expected result: The uris (LND) or binding/address (CLN) list contains <your_pubkey>@tunnelsats_ip:tunnelsats_port.

2. Target Node Outbound IPv4 Route Audit

Inspect the active IPv4 egress route used by your target node container:

LND IPv4 Egress: 
start-cli package attach lnd -- curl -s https://api.ipify.org
Core Lightning IPv4 Egress: 
start-cli package attach -i lightning c-lightning -- bash -c 'exec 3<>/dev/tcp/api.ipify.org/80; printf "GET / HTTP/1.1\r\nHost: api.ipify.org\r\nConnection: close\r\n\r\n" >&3; cat <&3 | tail -n 1'

Expected result: Returns your numeric TunnelSats server IP (e.g. 83.228.229.56) when WireGuard gateway routing is configured. If your residential IP is returned, outbound peer traffic is routing directly via your home connection.

3. Target Node IPv6 Isolation Audit

Verify whether IPv6 connectivity is unroutable or accessible:

LND IPv6 Egress: 
start-cli package attach lnd -- curl -6 -s --connect-timeout 5 https://api6.ipify.org
Core Lightning IPv6 Egress: 
start-cli package attach -i lightning c-lightning -- bash -c 'timeout 3 bash -c "exec 3<>/dev/tcp/api6.ipify.org/80" 2>/dev/null && echo "LEAK" || echo "BLOCKED"'

Expected result when Allow IPv6 is OFF: Network unreachable or connection timeout.
