Frequently Asked Questions

How do I set up and activate TunnelSats on StartOS?

Setup consists of simple steps across TunnelSats, StartOS Gateways, and your Lightning node:

  1. Order or Activate Tunnel: Select your target node, server region, and plan on the dashboard to order a tunnel, or paste an existing config under Bring Your Own Config.
  2. StartOS Gateway: Go to System → Gateways, delete any existing TunnelSats gateway first (updating an existing gateway cannot change its classification type), click Add Gateway, choose WireGuard, paste the configuration, and connect.
  3. Target Node Announcement: Confirm your node advertises your TunnelSats external host and port (e.g. LND → Config → Custom External Host).
  4. Firewall Port Toggle: In your target node (e.g. LND → Interfaces → Peer Interface or Core Lightning → Interfaces → Peer), find your TunnelSats public IP (<VPN_IP>:9735), and toggle it ON. When StartOS prompts to test port 9735 in "Address Requirements", click "Later".
  5. Set Outbound Gateway (Full Egress Privacy): In your target Lightning node (e.g. Services → LND → Actions → Set Outbound Gateway), select TunnelSats to encapsulate all outgoing peer connections, gossip, and ping/pong packets.
How does In-Container Clearnet VPN routing ensure zero residential IP leaks?

Standard VPN integrations often only tunnel inbound port forwarding, which leaves outbound peer connections, channel gossip, and keepalive pings routing over clearnet ISP interfaces.

TunnelSats works with StartOS native gateway routing to encapsulate both directions:

  • Inbound: WireGuard forwards incoming traffic to your dedicated port directly into your node container.
  • Outbound: Pinning the Outbound Gateway in your node directs all egress traffic through the encrypted VPN tunnel, preventing your home ISP address from ever appearing in Lightning gossip or peer handshakes.
How does multi-node routing work between multiple Lightning nodes (e.g. LND and Core Lightning)?

StartOS allocates host port 9735 to whichever Lightning node was installed first:

Standard Lightning communication occurs on port 9735. TunnelSats WireGuard gateways forward incoming peer traffic specifically to host port 9735. Any secondary node installed later receives an arbitrary high host port.

Guidance: Install the Lightning node you intend to use with TunnelSats first. If another node was already installed first and claimed port 9735, uninstall that node and reinstall the target node so it rebinds to host port 9735.

Note: Core Lightning's peer interface is named "Peer", while LND's is named "Peer Interface".

How does the 100 GB monthly bandwidth allowance work?

Each TunnelSats subscription includes 100 GB of monthly bandwidth for Lightning peer gossip and channel routing traffic.

Reset Cycle: Bandwidth usage resets to 0 GB at 00:00 UTC on the 1st day of each calendar month.

100 GB is sized generously to cover intense node activity and large channel topologies. Status telemetry is queried on-demand when you open the UI to keep VPN servers responsive and avoid background polling overhead.

How do I backup or export my WireGuard configuration?

You can export your complete, sovereign WireGuard configuration file at any time:

  • StartOS Actions (Secure & Authenticated): Open TunnelSats → Actions → Export WireGuard Configuration to view and copy your configuration. Exporting via StartOS Actions requires operator authentication to protect your private cryptographic key.

Keep this file secure! It contains your private cryptographic key and allows restoring your tunnel on any device.

What happens if my subscription expires?

When your subscription expires:

  1. The WireGuard tunnel drops — your node can no longer receive inbound connections via the TunnelSats IP.
  2. Your Lightning node's Custom External Host setting in StartOS will point to an inactive address until renewed or cleared.

To renew: Click Renew Subscription on this dashboard at any time before expiration. Your existing cryptographic keys and assigned ports will be extended seamlessly without downtime.

Does TunnelSats support IPv6? What happens if I enable IPv6?

No, TunnelSats is an IPv4-only WireGuard VPN service.

Because TunnelSats tunnels IPv4 traffic only, any IPv6 traffic will route directly through your residential ISP connection, exposing your home location.

We recommend keeping your node configured with IPv4 / Tor only. If you explicitly need dual-stack and accept revealing your home IP on IPv6, turn ON Allow Home IPv6 Coexistence under ⚙ → Configure.

How do I independently audit and verify my node endpoints via CLI?

You can audit announced endpoints and active egress routes directly from the StartOS host terminal using start-cli:

1. Gossip Announcement Audit 

start-cli package attach lnd -- lncli --rpcserver=127.0.0.1:10009 getinfo

2. Outbound IPv4 Route Audit 

start-cli package attach lnd -- curl -s https://api.ipify.org

Expected result: Returns your numeric TunnelSats server IP, confirming outbound traffic is fully encapsulated.
